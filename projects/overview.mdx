## The project template

Every project section contains these pages:

1. **Overview** — what it does, who owns it, links to repo and boards
2. **Setup** — from clone to running locally
3. **Architecture** — components, data model, connections to other systems
4. **Decisions & gotchas** — why it's built this way, known sharp edges
5. **Runbook** — deploy, monitor, debug (only if it runs in production)

Keep shared practices out of project pages: things like git workflow and deployment conventions live in [How We Work](/how-we-work/git-workflow) — link there and document only what this project does differently.
